Pre-Demo Checklist

  • ArgoCD synced — Application rx-demo shows Synced + Healthy
  • Credentials loaded — Env vars set on demo-wall Deployment (see Environment Setup below)
  • Load active — Start on scenario/baseline; loadgen pod running
  • Jaeger URL — Set JAEGER_QUERY_URL on storefront if you want trace deep-links to work
  • Audience access — Share storefront URL; keep platform UIs on presenter screen only
  • End on load-off — Switch to scenario/load-off after the demo to stop load

How Credentials Are Discovered

The Demo Wall reads credentials automatically from cluster secrets — no manual setup required. If a password field above is blank, check that the relevant secret exists on this cluster.
CredentialAuto-discovered fromFallback env var
ArgoCD password argocd / argocd-initial-admin-secret → key password ARGOCD_PASSWORD
Kommander / NKP SSO password kommander-default-workspace / dkp-admin-user-password → password
then kommander / dkp-admin-user-password 		KOMMANDER_SSO_PASSWORD
ArgoCD username Hardcoded admin (standard for ArgoCD) ARGOCD_USERNAME
Kommander SSO username Defaults to admin KOMMANDER_SSO_USERNAME
Kommander URL Auto-discovered via traefik-forward-auth-configmap provider-uri and SSO redirect probe KOMMANDER_PLATFORM_BASE (override if URL resolves wrong)
Storefront trace links Not applicable — set JAEGER_QUERY_URL on the storefront Deployment to enable deep-links JAEGER_QUERY_URL on frontend
If a password doesn't appear, verify the secret exists: 
# ArgoCD
kubectl -n argocd get secret argocd-initial-admin-secret

# Kommander / NKP SSO
kubectl -n kommander-default-workspace get secret dkp-admin-user-password
